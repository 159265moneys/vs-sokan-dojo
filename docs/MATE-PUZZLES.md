# 詰め・逆詰め

「1手・2手・3手」は黒の配置回数。白の応手は数に含めない。

## API

`makeMatePuzzle({mode:'attack'|'survive',moves:1|2|3,seed?})` は既存の練習局面と互換の `board / answers / variantId / lessonId / label / goal / steps / metadata` と、`type:'mate'`、`certificate` を返す。

`createMateState(position)` で状態を作り、`judgeMateMove(state,i)` で判定する。状態・入力盤面は変更しない。戻り値は `correct, done, state, feedback, refutation, refutationColor, whiteMove` に加え、`replay, finish, status` を持つ。

- `state.ply`：自動で置かれた白を含む半手数。
- `state.ownMovesPlayed`：回答した黒の配置回数。
- `replay`：今回の黒と白の遷移。誤答では黒の誤答から白の五連まで。
- `finish`：正解後の五連までの確認手順。`status:'forced-win'`のとき利用する。
- `certificate.line`：代表正解手順。白を含む`{i,side}`の配列。
- `certificate.finish`：代表正解手順の後に続く勝ちの確認。
- `certificate.branches`：逆詰めの全正解手と次の証明状態。
- `certificate.wrongReplies`：その状態の全誤答点から、直ちに五連を作る白の応手への対応表。
- `status`：`continue / five / forced-win / failed / outside-scope`。

## 詰め

五連、長連、両端の空いた四、四四、四追いから生成する。黒が実際に五連を作るまで回答が必要。各段階で残りの配置回数以内に終わる四追いを検査し、同等の強制手・両側の勝ち口を受け付ける。完全な一般詰め探索ではなく連続四の範囲である。

誤答に白の即勝ちがある場合だけ具体的な負け手順を返す。四追いの範囲で確認できない手を、必ず負ける手とは呼ばない。

## 逆詰め

各回答状態ですべての合法な黒の手を列挙する。黒がその場で五連を作る手を最優先で正解とする。除外するすべての手には、その直後に白が五連を作る具体的な点が必要。反例を得られない候補を含むテンプレートは問題として採用しない。エンジン評価値による判定はない。

3手の基本形は次の通り。

- 黒：H6 H7 H9 G8 I8 I7 I10 C3。さらに手番を整える無害な3石。
- 白：H5 E8 D4 E5 F6 G7 D6 E7 G9 F12 G11。
- 正解：黒H8、白H10、黒F8、白J8、黒I9。

白の即勝ち点は順にH8、F8、I9。各状態で他の黒の全合法手が直ちに白の五連を許すことを検査する。黒の正解は四を作るため、白の途中の応手も強制される。最後の黒I9ではI6とI11の二つの勝ち口が残る。全合法な白応手に対して白自身は勝てず、黒が次に五連を作れることを追加検査する。

この最後の盤面はまだ五連ではない。画面は「勝ち確定」とし、`finish`で残りの白・黒を再生できる。「3手で五連」とは表示しない。2手と1手の版は、この正解列の途中の黒番から始める。

1手版には、相手の四を防ぎながら自分の五連を作る形、飛び四の隙間で同時に勝つ形、双方に活四があって自分の両端どちらでも勝つ形も含める。

## 変形と検証

回転・反転・平行移動を行う。手数調整用の石は重要な形と空点から離して再配置し、その後も全誤答と正解手順を再証明する。variantIdは戦術に必要な色付きの石配置を正規化して決め、無関係な調整石や対局IDでは習得数を増やさない。

テストでは六つの設定、複数seed、全正解枝、各状態の全合法誤答、最終局面の全合法白応手、五連の成立、回数、入力不変性を検査する。この問題集合の局所的な保証であり、初期局面からの完全必勝戦略ではない。
