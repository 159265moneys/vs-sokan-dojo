# 学習体験の再構築仕様（5担当の知見を統合）

対象: 15×15自由五目、黒先手、禁手なし、5以上勝ち。2026-11-11。

## 画面の役割

最上位は 学ぶ / 対局 / 振り返り。学ぶ内はレッスン・実戦問題・復習。振り返りに棋譜履歴・勝敗集計を統合。対局に教材ショートカットを置かない。進行中対局・学習・検討の状態はタブ移動で消さない。

盤は幅最大、393×852で盤本体389×389以上。ヘッダー44、状態欄40、盤、操作48、残りを固定情報領域、下タブ56+safe bottom。説明はその領域内でスクロール、盤・操作位置を変えない。単元一覧・履歴は明示的な画面移動で開く。

盤入力は仮置き→「ここに置く」。未選択時は押せないボタンではなく状態表示「盤をタップ」。拡大選択を共通化。対局中は待った・ヒント・盤拡大。投了はメニューで確認。

## 教材

基礎を延々繰り返させない。単元選択は開放し、診断/実戦問題からも入れる。導入は短い盤面上の実演、次に自分で選ぶ、相手が応じた後も続ける。段階は勝ちの優先→形の条件→二方向の連携→先回り防御→四の順序→受け四の反撃→分岐→実戦。

単元ごとに成立例と条件が変わる例、代表誤答の反証を用意。問題数を回転・移動だけで水増ししない。主問題群は非自明な勝ち切り/先回り/候補比較/反撃の識別。四の穴埋めは入門の少数のみ。

確定勝ち、限定目標、推奨、自由比較を区別。唯一最善が不明なら探索上の一点を唯一解にしない。誤答が即負けでない場合は負けと表示しない。

学習データには初期盤・自分/相手の手順・複数応手・別解・ヒント・反証・強調する石/空点・概念系列・出典/検証条件を保持。進捗は閲覧、補助つき、初見自力、再試行を区別。旧進捗を新教材の習得へ自動昇格しない。

## 振り返り

終局から自動で重要場面へ。数値スコアで悪手を説明しない。実戦の一手→相手の機会→結果→改善を同じ盤で追い、構成石と勝ち口を強調。仮想の反証と実戦棋譜は別データ。すでに防げない最後の一手を責めず、防げた前の場面を優先。

具体的な勝ち/脅威の証拠がない評価差だけを敗因にしない。示す代案が局所防御であれば「この勝ち筋を防ぐ」とし、全局の勝ち保証にしない。試し直しと、関連単元の未見問題に接続。通常の一手ずつ棋譜再生も残す。

## 技術的な保護

Rapfi・ルール・既存の棋譜/進行中対局・素材/テーマ・SEを維持。学習 v2、レビュー v2 を純粋ロジックとして切り出し意味のあるテストを追加。CPUタブ離脱時に二重着手/結果消失しない。エラーは状態欄で再試行可能にする。ユーザーデータを消す移行は禁止。

## 検証

下記5担当の知見を統合した本仕様に従いproduction実装。教材は初期合法性、全正解/別解、誤答の説明と盤の一致、相手の別応手、元盤不変を確認。レビューは即勝ち・先回り失敗・逆四・既に詰みの誤帰責防止。ブラウザは初回入力/誤答の反証/継続手/タブ往復/棋譜から再挑戦/3難度/安全領域と固定寸法を確認。学習効果の実証やAAAを検証なしに表示しない。

## 5担当の根拠と採用判断

1. pedagogy_research: RIF規則と本作を区別、Allisの先手必勝研究と有限教材を混同しない。Renju入門書の攻めの準備/防御を自由五目で再検証。独自A〜Dは全応手を独立検査。四三の受け四による強制敗北、一手先の二重攻撃防御、三三後の方向切替を採用。[詳細](pedagogy-research.md)
2. othello_learning_research: オセロ連盟の一石違い比較、Othello! JAPANの相手応手別説明、Lichessの誤答と再試行、Chess.comの局面対局を確認。単元内に条件の異なる対照例と継続判断を採用。[詳細](othello-learning-research.md)
3. human_ux_research: Apple HIGと現コード/実画面の問題を照合。3タブ・固定盤・仮置きと確定・盤上の因果強調・状態保持を採用。[詳細](human-ux-research.md)
4. boardgame_product_research: 任天堂、Chess.com、Lichess、ぴよ将棋、AI Factory等7製品の一次資料を比較。多機能の模倣ではなく対局→重要局面→指し直し→再戦を採用。既存3難度は維持。[詳細](boardgame-product-research.md)
5. gomoku_knowledge_research: 自由五目の脅威/反撃を扱う作者の一次資料、Gomocup自由15部門を区別。572個の五セル窓で独立検証した方向転換の四追い、静かな二系統の準備、攻防兼用の防御を採用。静かな準備はH8だけでなくF8も勝てるため別解を拒否しない。元の初期局面に即勝ちがないことと全応手を検証。原データ artifacts/gomoku-research。調査記録は[知識・出典報告](gomoku-knowledge-research.md)。[作者一次資料](https://sortingsearching.com/2020/05/18/gomoku.html)

これらは学習効果を実証した研究結果と、製品の存在・挙動・設計意図を混同しない。新教材の妥当性/操作性は実装後に検証する。

## 実装分担

- root: 新アプリ状態/3画面/棋譜保持/学習・レビューの統合、HTML/CSS、盤の強調、ブラウザ検証、公開。
- pedagogy_research: curriculum.js / learning.js / learning.test.mjs。教材・比較・複数応手・段階ヒント・学習記録。
- gomoku_knowledge_research: causal-review.js / review-worker.js / causal-review.test.mjs。盤面の事実、検証できる因果、局所防御と勝ち証明の区別。
- UIUX担当は実装後の独立評価。CSSなどの同時編集を避ける。

旧modulesはデータやテスト資産として残すが新UIから旧教材/旧評価差レビューへの導線を除去。新UIを旧app.jsへ継ぎ足すのではなく、新しいstate/controllerへ置換する。
