# 反実仮想と型を中心にした振り返り

2026-11-11。ユーザーの追加指摘：一手ずつの事実報告では学習にならず、どこへ打てば何を防げたか/何を作れたか、研究で扱った型の認識が必要。

## 変更

- 重要局面は「要点」から開く。実戦の手→代案、型、具体的な相手の受けと次の攻めを最初に示す。
- 例：実戦J8に対し「H8なら四三で勝てた」。横の四で白J8を受けさせ、縦の三からH10へ伸ばせることを説明する。
- 相手に勝ちを許す手だけでなく、作れた勝ち筋と、実際に使えた勝ち筋も抽出する。別の勝ち方が未確認の手を敗着とは断定しない。
- 全手再生でも、該当手には同じ改善の説明を表示する。「この手を比較する」から元盤と改善手順を比較できる。
- 型名は盤の上に表示。型を切り替えると、発光と説明もその型へ切り替わる。関連教材へ移った後も元の検討状態を保つ。

## 発光の根拠

`review-patterns.js` は活三、飛び三、四、飛び四、両端の四、四三、三三、四四、受け四、逆四を盤の空点と相手石から判定する。2石が同じ線にあるだけの接続、外側が塞がって伸びない三は型として発光させない。

四三・三三は異なる軸と共有する石を持つ組として扱う。構成石・二方向の線・必要な空点をデータ化し、認識した型だけに発光を付ける。予定の形は「狙う型／防ぐ型」として示し、既に完成している形と区別する。

受け四は、相手の五の完成点を塞ぐ一石が自分の四にもなる場合。逆四は相手の三へ四で応じる場合。両端の四・四四はより強い形として優先し、同じ石に対する単独四の重複表示を避ける。四三の受けが相手の四になる反撃も確認する。

四追いは証明済み手順から構成する。両フクミは、すぐ三や四を作らない準備候補を選び、相手の全合法応手それぞれに後続の四追いがある場合に限って提示する。単なる二方向の接続を両フクミと呼ばない。

## 証明と探索範囲

型の成立と強制勝ちは別。三三・四三という名前だけで必勝とは表示しない。四による攻撃は既存VCF検証、三・静かな準備は全合法応手の後続VCF検証を用いる。通常は9半手、VCF部分450ノード、静かな候補は各局面2候補まで。三による攻撃を挟む分岐は深さを制限し、各防御の全合法応手を確認する。実戦に現れた相手手は候補の順序に使うが、それにしか応じない前提では証明しない。これは全最善手・一般VCTの完全探索ではない。失敗・打ち切りは未知のまま。

防御の代案も、示した勝ち筋を消す局所的な改善と、勝ちまで証明した手を区別する。表現は型と具体的な勝ち筋に結び付け、全局が救われる保証に変えない。

## 検証

さらに実戦の連続する三の攻撃と探索手数上限を検査し、既存65件と合わせ76件成功。ブラウザーで、J8→H8の比較、四三の2方向の発光、受け四を防ぐJ8の提案、全手再生からの比較、型から教材への移動と復帰を確認。393×852・safe59/34で盤389×389を保持。

## 実戦で見つかった追加の不足

公開版に残る22手の敗局では、VCFだけの解析で改善場面が0件になった。飛び三→活三→三三と三をつなぐ攻めを全応手で検証するよう拡張し、13手目L6に対するK4の局所改善を抽出。相手が実際に証明済みの攻めを開始した後の15/17/19/21手目は、すでに避けられない受けとして区別する。

探索が深くなった結果、以前は確認できなかった勝ち筋も見つかった。実戦J8も勝てるがH8からの四三に短い既知の手順がある例は、誤りとはせず「H8からも四三で勝てる」という比較にする。実戦手を不当に敗着にしない。

開発機では実戦22手の解析が約2〜3秒、一部の合成局面のテストは約16秒。Workerで実行しており画面離脱・中断は可能。端末性能は別途確認が必要。
