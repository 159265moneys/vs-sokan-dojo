# 学習経路 v3 の実装

2026-11-11。目的は、固定問題の再現から空盤の実戦へつなぎ、到達を測れる学習経路にすること。人間の「確実・最短・完封」は未実証なので、機能完成と効果認定を分ける。

## 優先順と所有

1. 露出・習得の台帳：learning_evidence_v3 が learning-path.js / learning.js / testsを担当。見本/既知盤の再入力を初見にしない。異なる2familyの初回確認、24h+別日で新構造盤の保持確認、無補助実戦遂行を別軸にする。旧棋譜維持、旧達成の昇格なし。
2. 未見確認バンク：assessment_content_v3 がassessment-bank.jsと証明tests。通常lessonから隔離、各unit4問/2family以上が目標。座標変形だけで水増ししない。
3. 空盤から課題対局：guided_journey_v3 がjourney.jsとtests。自由な黒の一手、CPU白の異なる応手、構築/守備後の再展開/五連までを本人が担当。practiceのみ無補助、guidedとrecoveryは補助記録。
4. rootがapp/curriculum/CSSを統合。標準の次の一歩、診断からの開始、独立確認、局面からの継続、通常対局と練習の区別を接続。
5. 最強10局チャレンジ：新seriesIdで空盤・8秒strength100・無補助・10終局全勝を観測。投了/中断/補助を隠さず、代替の勝ちで穴埋めしない。将来の無敗を保証しない。
6. 機能・棋理・実画面を検証し、新しい独立担当へ教材として再監査。

## 固定制約

ヘッダー/盤/石の素材を保持、盤389×389/393×852、情報量で盤と操作位置を動かさない。3主タブ。対局は対局だけ、教材は学ぶ内。必要な戦術説明は残す。スケジュール・通知・heartbeat・自動再開なし。保持はユーザーが後に手動で開いた際の日時判定だけ。

## 統合契約

base curriculumVersion 2026-11-11.2を保持し既存進行中lessonを壊さない。assessmentProblemsだけproblemsへ追加、units.problemIdsはlessonのみ（priorityの基本の受け1題を追加し22題）。別台帳sokan.learning-path-v3とjourney-v3を使い、新しい判定へ旧達成を繰り上げない。

Engineは共通1つ。普通対局の応手を破棄せず、課題対局は検索が空いた時に応答。new/resume/cancelの世代とidを照合し、別対局への応手混入を防ぐ。課題対局の履歴は通常戦績から分離。


## 実装・実画面の確認（2026-11-12）

- 36確認盤は22基礎課題から分離。priorityは「自分の即勝ち」「自分に勝ちがなく唯一の即負けを止める」の対照条件を含む。確認の初期目標文は共通の「黒の一手を選ぶ」とし、正答側を先に教えない。
- 採点の弱い代替、保持後の失敗無視、失敗条件と違う再確認、未発生の方向転換を標準ルートが飛ばす問題、投了表示の欠落を独立監査で検出し修正。具体反例と再確認は独立報告に保存。
- 空盤構築の完走と、必要な横・縦の分岐経験を分ける。既知の分岐練習を無補助の空盤実戦として扱わない。型の発光は指示文が示す実三・四・二重攻撃に対応する。幾何的な2石連携は通常のfocusで区別。
- 振り返りの採用手をそのまま引き継ぎ、CPUの実応手から本人が継続する。元の棋譜のprefixとbeforeを保存し、課題の開始配置は本人の誤りとして解析しない。

### ブラウザーで実操作した経路

393×852、上59/下34の安全領域を再現したローカルページをCUAで操作。実機iOS 27.0.1の実行検証とは区別する。

1. 誤答→原因→相手の五連手順。旧保存データの理由欄が空になる問題を目視で発見し修正。D10なら先に勝てた/白N4で完成、を表示。
2. 空盤buildの最初の配置、実白応手、進行保存と再読み込み。
3. branchで本人H8→教材白E8→本人H9→実CPU白H10→本人H5。残る縦の三の発光、四への候補、本人の五連と3目標の完了を確認。
4. 実戦22手棋譜の13手目L6→K4の改善説明、飛び三の発光、実戦/改善の切替、本人K4の指し直し、CPU白K6から継続を確認。
