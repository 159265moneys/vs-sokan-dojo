## 盤と因果説明

五連と完成点は、空点へ仮着手した後に四軸の両側へ連続石を数えて求めた。製品の `game.js`、`learning-objectives.js`、生成の `reserve-oracle-v5.mjs` は判定に使用していない。

`safe-four` は黒の完成点を作る全合法手について、白の合法応手を調べ、黒の完成点を消した応手が白の五連・完成点を作らないかを確認した。`two-directions` は白・盤端で区切られた自由な直線区間から、本人の点と指定支持石が5点以内に収まり、異なる二軸へ接続できるかを調べた。活三は次の仮着手で連続四となり、その両外側が盤内の空点になることから求めた。

その計算で134題の正答、全受理手、conditions/counterの全完成点、prepareの有効方向、混合判断の即五連優先が一致した。全局唯一最善や長期必勝を保証する問題へ拡大解釈していない。

説明根拠は別に、盤全体の直線から5点・6点区間を組み立てて照合した。

- 134題のreasonを検査。branch/prepareの候補106件、counterの軸別支持プロフィール132件が実盤と一致。
- conditionsの完成点・遮断白、branchの支持石を含む四・実完成点・外側の遮断白、prepareの指定点を含む活三、openingの接続区間・遮断白・近接/遠方が一致。
- counter-ray1の25題は初期石150個を一つずつ除き、黒候補後の完成点か白応手後の完成点が変わることを確認。遠方の無関係な石を因果的な支持として数えていない。
- 選択肢で共有される説明を一度ずつ数えた293フレームで、lastは実石、cellsは実石、pointsは空点に対応。選択肢ごとの重複を含む製品テストの735フレーム検査も成功。

## 新規性と供給の境界

独自のD4・平行移動正規化で、既存教材・単元図・戦略図・基礎手順・expert棋譜prefixの776出現、447構造を収集した。134予備初期盤との位置衝突、予備同士の位置衝突、予備の293説明フレームから別予備初期盤を先に見せる衝突は、いずれも0件だった。

全盤の違いだけで新規性を認定していない。68件の既存比較教材と予備について、指定支持、関連白、候補、完成点、独自計算した全受理手などを役割付き座標として再構成・正規化した。89題では補助石を除外した状態で比較し、既存教材との局所重複、予備同士の局所重複は0件だった。固定の支持間隔・穴・関連軸・閉塞が異なる有限の局所条件であり、ID数を独立技能数や教育効果へ換算できるという意味ではない。

選題は登録済み教材のdomain/supplyを用い、同条件の未見原確認を予備より優先する。任意のsupplyタグ・未登録domain申告・重複候補で資格や残数を増やさない実装を差分で確認し、全15domainの正式供給テストでも通過した。schema/curriculumVersionを進めて旧履歴を捨てる移行は入っていない。

## 答えの非表示と最終修正

全260問題の初期viewは、設問のgivens、短い目標、選択肢のid/titleだけを表示経路に渡す。ヒント使用履歴は累積したまま、retry・復元・次の決定・画面再入場で表示を閉じる。正しく予測しただけで次の本人入力が残る場合、解説の自動再生を行わない。明示した解説・見本・ヒントは支援として記録する。

guided課題対局では、未要求の指示文・候補評価・推奨点を `rawFrame` と `renderPanel` の双方で遮断していた。盤を選択しただけでは `previewJourneyMove` を表示用に呼ばず、ヒント操作をした現在の一手でのみ開く。着手・再試行・画面離脱・再読込で閉じる。本人が置いた手の事後フィードバックと、次の未回答手への助言を分ける契約である。

審査中、別の教材評価担当が `opening-two-plans` の判定基準不足と、続きの未回答手へ方向を先に告げる表示を指摘し、実装担当が `5e0932d` で修正した。本審査ではその修正を再確認した。

- 初期の問いは「今の黒石につながる候補」を選ぶ基準を持つ。
- 既存exerciseを変更せず、trustedな問題定義の表示用promptで「白の応手を見て、残る方向に活三を作る」とする。
- 実際の画面が優先する `feedback.title` と `goal` の両方を中立化。二つの白応手と旧attemptの復元で方向名・解答座標・正解マーカー・本文解説を先出ししない。
- 攻略書の一手ずつ交互に置くルール説明も補われている。

この担当はブラウザーを操作していない。実画面についてはrootが操作した記録を補助証拠とし、保存された次の画像を目視した。初期問題と未要求の課題対局に正解マーカーはなく、要求後のヒントには方向と点の表示があり、修正後openingの続きは方向を伏せた目標になっていた。画像だけで全操作の正しさを推定せず、上記のコード経路・実API・対象controllerテストと併せて判断した。
