# 実戦棋譜ドリルの収録元と検証

## 出典

`dist/record-drill-seeds-v7.json` は、実際に空盤から終局まで打った棋譜の途中局面を収録する。棋譜と問題の対応は `records`、`questions[].source`、`questions[].prefix` に残す。表示名は **収録棋譜** であり、利用者自身の対局履歴として扱わない。

出典は次の二つに限定する。

- `dist/expert-courses.json`：既存の Rapfi 対局３局。黒白とも strength 100、１手 8000 ms、独立したエンジン。自然な初手からの対局１局と、白２手目だけを H7 / H6 に指定した対局２局。指定手は元データと収録メタデータの `forcedOpening` に明示する。
- `data/record-drill-source-games-v7.json`：今回、同梱の Rapfi 実行ファイルで実際に最後まで打った追加対局。黒白別エンジン、単一スレッド、freestyle15。各手の採用座標、手番、設定思考時間、実測時間、エンジン出力を保存した。初手も含めて全着手が探索結果であり、配置問題の再構成や、石の付け足しは行っていない。

`artifacts/v6-main-playthrough-export.json` 等の利用者の対局・個人履歴は収録元に含めない。持ち込んだ局面の色交換、回転、平行移動、間引き、局所切り出し、ランダムな石の追加も行わない。重複判定で回転・平行移動を同一視する場合も、出題盤面と棋譜は元の座標のまま保存する。

追加対局の黒は１手100 ms、白は strength 100・１手500 ms。既存８秒対局とは別設定であり、追加対局を「最強CPU対局」として扱わない。`level` はアプリの互換分類であり、実際の条件は `provenance.black` / `provenance.white` と凍結入力の各手に記録する。

## 抽出条件

`scripts/build-record-drill-seeds-v7.mjs` は `extractRecordDrills` を呼び出す。独自の答え、作問用盤面、勝敗ラベルは作成しない。

- 黒の着手前で14石以上。盤面225点を保ち、初手から対象手の直前までの全着手を再現する。
- 出題時点で黒白どちらにも即時の五の完成点がないこと。一手勝ち、一手の強制受けは除外する。
- 少なくとも５手の証明を必要とする。３手で終わる達四だけの終局直前問題は収録しない。
- 探索上限は９手、450ノード、quietDepth 2。未証明局面を不正解や安全な局面と決めつけない。
- 同一局では原則６手以上離し、証明手順が重なる連続局面をまとめる。終わりの簡単な受けから逆に問題を増やさず、確認できた判断の先頭を優先する。
- 正解候補は `judgeReviewMove` の確認を通した候補のみ。収録側で候補を増減・捏造しない。
- 問題が得られない対局は凍結入力と抽出監査には残し、配布する `records` には含めない。

## 証明範囲

勝ち筋の `forced-win` は、局面から確認できた強制勝ちの手順を持つ。白の応手が何でも同じ座標列で勝つという意味ではなく、証明の種類によって応手を分岐させる。

守りの `line-prevented` は、実戦の着手後に確認できた白の攻めの具体的な手順を、候補手が阻止するという証明である。対局全体の敗因がその一手だったこと、他の白の勝ち筋が存在しないこと、その候補で引き分け・黒勝ちを保証することは証明していない。特に探索範囲より長い攻めで既に悪化していた可能性は残る。対局の終局結果と、候補手の証明範囲を区別する。

全手を走査済みの `coverage.complete` は全局面の勝敗を解いたという意味ではない。`unknownPlies`、`unavoidablePlies`、除外理由、抽出数を `audit.records` に保存する。

## 再生成と検証

```sh
node scripts/build-record-drill-seeds-v7.mjs
node scripts/build-record-drill-seeds-v7.mjs --check
node --test tests/record-drill-seeds-v7.test.mjs
```

通常の生成と `--check` は凍結された入力棋譜だけを読み、CPU対局を再実行しない。入力ファイルの SHA-256、出典、全棋譜、抽出結果が一致することを検証できる。`--check` は出力ファイルを書き換えない。

追加の実対局を採録する場合だけ、明示的に次を実行する。

```sh
node scripts/build-record-drill-seeds-v7.mjs --record-games 3
node scripts/build-record-drill-seeds-v7.mjs --record-games 1 --black-strength 10
```

時間制限つきエンジン対局は端末・実行時の探索状況で変化するため、新しい採録自体は決定的ではない。採録後に棋譜を凍結し、それ以後の問題抽出を再現可能にする。既存記録は上書きせず追加する。エンジン設定と実際の終局結果を残し、期待した勝敗へ着手を改変しない。

テストでは、入力ハッシュ、エンジンハッシュ、初手からの合法性、終局後の着手がないこと、勝敗、手番、探索設定、元棋譜と全盤面の一致、出典区分、答えの初期非表示、問題の非重複、決定的な再抽出を検証する。
