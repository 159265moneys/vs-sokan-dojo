### P2: 正規の256件目のイベントを保存すると再開不能になる

対象は `dist/record-drills.js` の `checked` と `dist/record-drill-controller.js` の `resume`。

`checked` はイベント数が256以上の状態を全操作で拒否するが、255件から256件目への正規操作は許す。`restoreRecordDrill` は256件を復元できる。その後に必ず実行される `hide-hints` が失敗するため、再読込で続きへ戻れず、採点・ヒント・再挑戦も失敗する。ヒント、閉じる、再挑戦を同じ試行で繰り返す通常操作の累積でも到達する。

再現は、収録問を `startRecordDrill` し、`retryRecordDrill` を256回実行する。`events.length === 256`、`restoreRecordDrill(q, state)` は成功するが、`hideRecordDrillHints(q, state)` と `retryRecordDrill(q, state)` は「実戦問題の試行が不正です」となる。

### P2: 初期読込中に同期された新しい棋譜を古い一覧で消す

対象は `dist/record-drill-controller.js` の `initialize`。

`initialize(records)` は収録問題の非同期取得後、`finally` で開始時の `records` を再同期する。その待機中に新しい取込・終局の `syncRecords` が来ても、古い一覧が最後に適用され、進行中の抽出を取り消す。

再現は、`fetchSeeds` の応答を保留し、`initialize([])`、`syncRecords([22手QA棋譜])` の順に実行する。この時点でソース1件と抽出Workerがある。収録問題を返して初期化を終えるとソース0件・待ち行列0件になり、そのWorkerは停止し、自分の問題も0件のままとなる。次の明示的な同期まで自動生成が失われる。
