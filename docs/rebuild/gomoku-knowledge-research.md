# 自由五目15路：教材知識・出典・自作局面の検証

調査日：2026-11-11。対象：15×15、黒先、交互に一石、禁手なし、縦横斜めの**5個以上**で即勝ち。担当範囲は戦術の正誤、一次資料との対応、問題データの由来と証明。教授順序・画面設計の担当資料とは分ける。

## 採用判断

- 型の名前を当てるだけでは、四三・三三を実戦で使えない。成立するための空点、相手の逆四、強制応手で生まれる相手の攻め、攻撃順を局面の変化として扱う。
- 自作3局面を作成。黒番の合法局面であること、初形で終局していないこと、提示初手の後の相手の全合法手を検査した。合計620応手について、独立検証器と既存 `proveVCF` の双方で後続勝ちを確認した。
- 特に `quiet-dual-vcf` は初形に四を作る手がなく、H8も三・四を作らない。H8後は相手の208応手すべてに7手以内で勝つ。ただし **F8も勝てるため、H8を唯一解と採点してはいけない**。
- 3局面の「最善手が唯一」「提示以外の手は負け」「人間に対する難易度」は未証明。勝ちの証明と、敗北／唯一性の証明は別である。
- 実戦教材の第一候補は Gomocup の **Freestyle-15**。RIFのGomoku棋譜をそのまま本アプリの正解データにするのは不適切。

## 2. 正誤判定の基礎：見た目でなく合法な継続を数える

以下は本アプリ用の形式化。`W(B,c)` を「局面 B の空点に色 c を一石置くと5以上になる点の集合」とする。

1. 自分の `W` が非空ならその場で勝てる。相手の四を受けるより自分の即勝ちが先。
2. 自分に即勝ちがなく、相手の `W` が1点なら、その点以外は次の一手で負ける。
3. 自分に即勝ちがなく、相手の `W` が異なる2点以上なら、一石で両方を消せない。取る手がない本ルールでは既に受け切れない。
4. `W` の個数と「何本の線があるか」は別。重複する5セル区間を数えた結果を二つの勝ち点だと誤認してはいけない。
5. 自由五目の長連は失敗でなく勝ち。6個以上を「過剰に伸ばして無効」「六腐で防げた」と扱う教材は不適合。

### パターンカタログ

`X` は自石、`O` は相手石、`.` は空点、`|` は盤端。文字列は局所表示なので、必要な外側の空点を勝手に補完しない。

|概念|実装・教材で確認すべきこと|初心者に与えてはいけない規則|
|---|---|---|
|即勝ち|連続5以上の完成点。飛び四の内部の空点も含む|連続4だけを見る|
|単独の四|`OXXXX.`、`XX.XX` 等、次の勝ち点が1つ|四を作れば勝ち／四は必ず4石連続|
|達四|`.XXXX.`。両端という異なる勝ち点が残る|相手に即勝ちがあっても達四が優先|
|四四／二つの勝ち点|異なる完成点を同時に作る。自由五目では黒も合法|「黒の四四は反則」という連珠の指導を混入|
|三|一手で両端が開いた連続4にできる。単なる石数3ではない|両隣が一つずつ空いていれば常に三|
|伸びる三|例 `.XXX..` は右へ伸びると達四になる。左右2空点ずつは十分条件だが必須ではない|`..XXX..` 以外は三でない|
|飛び三|`.XX.X.`、`.X.XX.` は内部の空点で達四にできる|間が空いているので弱い／止める場所は外側だけ|
|伸びない三風の形|`O.XXX.O` はどちらへ伸ばしても達四にならない|見た目の3石＋両脇空点を機械的に三と数える|
|四三|四の強制応手の後にも、三から勝ちへ進めるかを確認|四と三のラベルが同時に付けば常に詰み|
|三三|二つの三の独立性、直接防御と逆四・即勝ちを確認|二つの三なら相手は何もできない|
|両狙い|二つの**具体的な勝ちの継続**と、それぞれの受けを表示|線が二方向なら両狙い成立|
|ノリ手|受ける一手が同時に相手の三・四になる。そこで手順を再計算|強制応手は盤上へ相手石を追加するだけ|
|逆四|三などにすぐ受けず、別の四で相手へ応手を要求。受けた後も元の脅威が残る場合がある|逆四があれば必ず攻めが失敗／三には必ずその場で受ける|
|呼手（こしゅ）|すぐ三を作らず、接続・将来の攻撃点を増やす準備|どの局面でも三を作る手が最善|
|ミセ／フクミ|次の複合攻撃、または四追いを可能にする準備を、具体的な継続で定義|静かな手を評価点だけで「妙手」と表示|
|早期防御|完成予定点・接続点・後の受け石を先に置ける場所を候補にする|三や四の目の前の端だけを止める|
|序盤の接続|連と剣先を増やす交点、端までの余地、相手の分断・反撃を比較する|中央・くら型・四つ目を作れば自動的に勝ち|

「先手」は黒番という意味と、脅威で相手に応手を要求する主導権という意味が混ざる。教材データでは `sideToMove` と `initiative` を別扱いにする。画面では必要に応じて「黒番」「攻めを継続」のような短い表示にする。

### 四三と三三の成立条件

四三では、初手の後に相手の即勝ちがないこと、四の唯一の受け点を置かれた後に継続が残ること、受け石が相手の四を作らないかを調べる。相手の四ができても、それを受けながら勝てる枝があれば四三は成立する。逆四を発見しただけで即不正解にしてはならない。

三三では、相手の応手を三の近傍だけに限定しない。相手は別の場所で五を作る、四を打つ、受けと攻めを兼ねる、後の接続点を占めることができる。「二つの形」ではなく、全ての合法応手に勝ちが続くことが証明条件。

## 3. VCF、VCT、静かな準備を区別する

|名称|このアプリでの厳密な範囲|必要な検証|
|---|---|---|
|VCF／四追い|攻撃側が各回、次の手の五を脅かす四を作る。最後は即勝ちか二つ以上の勝ち点|毎回の相手の即勝ちを確認。勝ち点が一つなら受けは一意。受け石が作る逆の四を次の局面へ反映|
|VCT／三を含む連続攻撃|四だけでなく、達四へ伸ばせる三を使う連続攻撃|AND/OR木。攻め側に一つ勝ち手があり、受け側の全応手で勝つ。盤全体の反撃を落とさない|
|静かな準備|現在三・四を作らず、将来の四追い・複合攻撃を用意|初手後の全応手に証明済み継続が必要。VCFの範囲外であることをバグと扱わない|

Allisらの脅威空間探索は、脅威を独立した候補として組み立てる考え方を示す。ただし脅威間の依存・衝突、受けによる反撃を解決しなければ勝ちの証明にならない。Czajkaの実装解説も反撃とrefutationを独立して扱う。これらの着想から、本アプリではヒューリスティックな「有力」と、全応手を通した「勝ち確認済み」を区別する。[Allisら](https://cdn.aaai.org/Symposia/Fall/1993/FS-93-02/FS93-02-001.pdf)、[Czajka](https://sortingsearching.com/2020/05/18/gomoku.html)

既存 `dist/game.js:99` の `proveVCF` は成功時に四追いの証明を返す。失敗・深さ切れ・ノード上限は勝ちがない証明ではない。返す `line` は代表応手列であり、VCTの全応手木ではない。教材の「相手の別応手」は別途保持すべきである。

## 4. 実戦の証拠と、未取得データ

**実戦に逆四が含まれる一次例**：Czajkaの記事の Example game 1 は OOOOO 対 ltgmk の実戦。作者が示す13手の終盤には、四、飛び三、白の逆四、黒の受け、元の三への白の受け、三三、達四という流れがある。これは「三にすぐ直接受けなければ負け」という説明への反例であり、同時に「逆四が一度あれば元の攻めは失敗」という説明への反例でもある。ただし16路・swapの対局なので、その図を15路へ切り取った問題は別途全応手検証が必要。[作者の実戦説明](https://sortingsearching.com/2020/05/18/gomoku.html)

**15路自由五目の実戦採取先**：Gomocup 2024は15路自由部門の導入を明示し、同ページから [完全結果・開始局面ZIP](https://gomocup.org/static/tournaments/2024/results/gomocup2024results.zip) にリンクしている。今回、リンク先確認まではできたが、Web取得はZIP非対応、ローカル取得はHTTP 403で、個別棋譜の中身は未確認。対戦者名・座標を推測して実戦問題を作ってはいない。[主催者の結果ページ](https://gomocup.org/results/gomocup-result-2024/)

将来採取するときは、元棋譜の自由15部門を確認し、開始局面と手順を保持し、5以上成立後の手を排除する。対局の勝者が打った手を自動的に唯一の正解にしない。投了局面には複数の勝ち筋があり得る。敗着の判定には、その手の後の相手の勝ちの証明に加え、打つ前に回避可能だった証拠が必要。

## 5. 自作問題3例：座標・応手・証明範囲

座標は既存アプリと同じ A〜O、1〜15、A15が左上。以下はすべて黒番。列記した黒・白を同じ添字で交互に置けば合法な履歴になる。各局面の石数は同数で、途中を含め既存の五はない。

### A. turning-vcf：曲がる四追い

```text
黒 C8 D8 E8 F5 F6 G7 H7
白 B8 F4 I8 J10 H10 L12 K13
```

初形の即勝ち点は両色とも0。黒が四を作れる初手は F8 と G8 の2点。

**証明済み**：`黒F8 → 白G8 → 黒F7 → 白F9 → 黒E7 → 白D7 → 黒I7`。白D7の代わりにI7なら黒D7。その他の受け外しには、その時点で残る五の完成点で勝つ。

- F8は横の四を作る。G8を強制してからF7が縦の四となり、F9の受けで横へ切り替える。
- F7後の縦F5〜F8はF4が白なのでF9が唯一の勝ち点。最後の横E7〜H7はD7とI7の2点が残る。
- G8は白F8を呼び、上の攻撃に必要なF8を相手石にしてしまう。11手以内のVCFは両実装で見つからない。ただしG8がゲーム全体として敗着という証明はしていない。
- F8後の白210合法手すべてに後続VCFを確認。最大7 ply。初形からの最短VCFは7 ply。

採点用途：四追いの継続を最後まで打たせる、F8/G8が呼ぶ白石の位置を比較する。G8を「必敗」と表示しない。

### B. quiet-dual-vcf：三も四も作らない両フクミ

```text
黒 D8 E8 F6 F7 H11 H12 I11 J12
白 C8 D5 J8 L11 H13 L10 M13 B4
```

初形の即勝ち点は両色とも0。**初形では黒が四を作る手が一つもない**。

**証明済み準備手：黒H8。** H8後も黒の即勝ち点は0。H8後の任意の黒の次手について「異なる勝ち点を2つ以上作る手」は0であり、H8は直ちに達四を作れる三も作っていない。

代表応手は次のとおり（各列の最初のH8は共通）。

|白の初回応手|黒の継続例|意味|
|---|---|---|
|F8 / G8 / F9|H10, 白H9, K13, 白L14, G9|下側を止められても斜めの達四へ|
|H10 / H9 / G9|F8, 白G8, F9, 白F10, F5|上側を止められても縦の達四へ|
|K13|H10, 白H9, F8, 白G9, G8|単純に決めた片側だけでなく、応手に合わせて接続を切り替える|

全208合法応手を列挙し、各応手後に5 ply以内のVCFを確認した。したがってH8から最大7 plyの強制勝ち。両端の受けを反転した枝や受け外しも、勝ち点集合で証明できる。

**複数正解の注意**：黒F8も全208応手に最大7 plyの勝ちがある。教材の課題が単に「勝つ手」なら H8とF8をともに正解にする。H8に限定する場合は「三・四を作らず準備する」という技能課題が必要。それでも全合法初手の唯一性までは調査していない。

候補H10では白G9、候補G8では白F9/F8/H8/F5に対し、「初手＋その後5 ply以内のVCF」という限定された証明が得られなかった。これらをそのまま敗着と呼んではならない。

この問題が示すこと：VCF検出器が初形で `proven:false` を返しても、実際には勝ちがある。検索範囲外と負けを区別する回帰ケースとして有用。

### C. dual-duty-defense：受けながら攻撃へ転じる

```text
黒 C8 D8 E8 F5 F6 G7 H7 A13 J4 L5 M8
白 B8 F4 I8 J10 H10 L12 K13 E9 D10 C11 B12
```

初形で黒の即勝ち点は0、白はF8で即勝ち。白B12〜E9の斜め4の反対端A13は黒なので、F8が唯一の受け。

**証明済み**：黒F8で受けると同時に黒の横の四になる。その後はAと同じ `白G8 → 黒F7 → 白F9 → 黒E7` で勝ちを続けられる。F8後の白202合法手すべてで最大7 plyの勝ちを確認。

この問題では **F8以外は白F8で直ちに負け** と断定できる。初形で黒の即勝ちがないため、他の場所の攻撃では間に合わない。Aと同じ勝ち筋でも、初手の理由が変わる対比として使える。初手だけでは易しいので、受けた後の勝ちまで実演させる用途。

### 防御へ転用する場合

Aの色を反転すれば、黒番で白のF8からのVCFを事前に止める素材になる。確認した候補では、黒H8には白F8から7 plyの勝ち、黒I7にも白F8から9 plyの別の勝ちがある。最終達四の片側I7だけを先に塞いでも、別方向の継続が残る反例になる。

黒F8/G8/F7/F9/E7の後は11 ply以内の白VCFが検出されなかった。しかし、これは白に他のVCTや準備手がない証明ではない。この段階のデータを「最善防御」「黒が助かった」という問題にはせず、既知の四追いを比較する限定課題または未採用素材に留める。

- `artifacts/gomoku-research/validated-positions.json`：全620応手の勝ち列、探索結果、候補初手、既存エンジンの結果。
- `artifacts/gomoku-research/candidate-checks.json`：Bの複数正解、H8後の静かな性質、防御への色反転候補の検査結果。

独立側は縦横斜めの全572本の連続5セル窓を前計算し、盤上の石の数で勝ち点を求める。既存側は `winningLine` の方向走査。勝利判定の方式が異なる2実装で照合した。全応手後の両色の勝ち点集合も一致した。

後続の四追い探索は攻撃側の選択を限定するが、四を受けない相手手はそのまま五を許すため、一意の受け以外を正当に省略できる。二つの勝ち点で終える場合も相手の即勝ちがないことを確認する。最初の準備手の後は省略せず全空点を調べた。成功は証明、失敗は範囲内で未証明として保存する。

検査ログの要約：`independentWindowCount:572`、`allDefenderRepliesCrossCheckedWithApp:620`、`validBlackToMovePositions:3`。探索予算は11 ply・100,000 nodesを上限とし、3局面の勝ち列はすべて7 ply以内。今回の証明では上限打ち切りは発生していない。

## 7. 教材データに必須の情報

```text
rule / boardSize / sideToMove / stones / origin
objective / motifTags / acceptedMoves
proofKind / proofScope / maxPly / budget / aborted
opponentReplies / winningContinuations
wrongMoveWitnesses / alternativeCorrectMoves
sourceURL / originalGameID / sourceRule / authoringNotes
```

`acceptedMoves` と `alternativeCorrectMoves` は、手で採点する場合に統合する。誤答には「評価が下がる」だけでなく、相手の応手とその後に何が失われたかを持たせる。勝ちが未証明の手を誤答にする場合は、題意自体が特定技能・手順の再現であることが必要。

問題生成時の受入条件：初形が合法、既存終局なし、正解に不要な一手勝ちなし、予定テーマ以外の簡単な解がないかを確認、別正解の受理、回転・反転時の座標と証明の再検証、端で必要空点が消えないこと、逆四と長連の扱い、誤答枝の実証。この検査を通過して初めて本番bankへ入れる。

「一石違い」では、変えた石を含む線だけを見ず、盤全体の新しい勝ち点と逆四も再探索する。誤答の負けが確定しないときは「この手順は止まる」と「この局面は負け」を分ける。

## 8. 強さと証明について守る表現

15路自由五目の黒必勝が研究で示されていることと、このアプリのCPUが最善応手を常に選ぶことは別。とくにユーザーが黒、CPUが白なら、先手の完全な勝ち戦略に対して後手CPUが必ず無敗であるという約束はできない。[Allisらの対象ルールと結果](https://cdn.aaai.org/Symposia/Fall/1993/FS-93-02/FS93-02-001.pdf)

「四追いを確認」「全応手で勝ちを確認」「指定探索範囲では未確認」は検証と対応する。「完全必勝法を習得」「最強CPUは絶対に負けない」「AIが選んだので唯一の正解」は今回の証拠からは言えない。

本番画面へこの報告の説明段落を持ち込まない。局面上で、必要空点、相手の受け石、二つの完成点、攻めの向きの変化を表示し、必要なラベルと短い状態に絞る。
