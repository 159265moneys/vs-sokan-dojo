# 未見確認バンク

2026-11-12更新。実装は `dist/assessment-bank.js`。通常レッスンと分離した36課題を収録する。9単元に4課題ずつ、19個の条件family。34課題は最初から盤入力、2課題は候補比較の後に白が打ち、残った線を盤入力する。

課題数、証明器の成功数、テスト件数は教材の整合性を示す。人間の上達、学校での保持、最強CPUへの勝率、最短学習期間の証拠ではない。確認の初見性・無補助・異なる条件・別日保持は `learning-path.js` の台帳で別に扱う。

## 通常レッスンとの境界

- `export const assessmentProblems` は既存 `Problem` schemaに従う。`curriculum.js` の全問題配列へ結合するが、`units[].problemIds` と見本フレームには入れない。
- `role: 'assessment'`, `skillId: unitId`, `family`, `branchId`, `requiresBranch` を持つ。単元IDは `priority / conditions / opening / defense / order / counter / branch / prepare / practice`。
- `family` は判断条件の系列。向き・平行移動・盤の番号を増やして新familyとはしない。盤全体のD4/平行移動fingerprintでも重複を検査する。
- `branchId` はこの盤での具体的条件。実際の白応手は既存の `replyVariant` と `history` へ記録する。異なる白応手を同じfamilyの新規課題とは数えない。
- `requiresBranch:true` は白の応手後に少なくとも一度黒を入力する課題。即五連と有限の防御目標だけは `false`。単なる初手正解で勝ち問題を終了しない。
- 未見の成立は問題IDだけでは決めない。説明・見本・ヒント・途中の正解案内・同形への露出は台帳で判定する。ここに答えが収録されているだけで未見成功を記録しない。

|priority|priority-defend-a / b|`prevent-immediate-loss`: 自分に即勝ちがなく、白の唯一の完成点を塞ぐ。片端を黒が閉じた連続四と斜めの飛び四。I10／E10を受けて局所目標を完了し、黒勝ちとは認定しない。|

|counter|counter-chain-a / b|`defend-and-continue`: 白の五連を防ぐ一石が黒の飛び四となり、その後の四追いを続ける。反撃を認識するだけの二択ではない。|

序盤比較の選択肢ラベルは座標だけで、「二方向を残す」など正解を教えるラベルにはしない。これらは表示された候補の構造比較であり、序盤の唯一最善・必勝認定ではない。残る形の盤入力は固定解答表ではなく、五セル・六セル窓による条件を満たすすべての着点を受理する。

## 静かな準備の限定された証明

4盤すべてについて、開始盤の全合法黒初手を列挙し、四を作る初手が0であることを確認した。したがって、最初から四追いを選んで準備段階を飛ばすことはできない。`initialFourCount:0` と、各盤の代表的な静かな手 `quietSetupMoves` を持たせる。

代表手は順に F8 / I9 / G6 / J7。この一手自体は四を作らず、その石を含む「次の一手で両端四になる三」も作らない。しかし白の全208合法応手のどれに対しても、以後の黒の四追いで五連まで勝てる。登録された白の表示分岐だけの証明ではない。

静かな代表手以外にも、三を作ることから全応手の勝ちを証明できる別解がある。有限の勝ちを達成するため受理する。代表手だけを唯一解にせず、別解の成功を「同じ静かな手を選べた」と解釈もしない。`quietSetupMoves` はこの区別を必要とする集計用の内部情報であり、初期盤に表示しない。

## データの出所

32課題は今回の自作。外部書籍・問題集の図や解説をコピーしていない。四追い・静かな準備の候補構成を有限証明器で選別し、採用された固定盤をデータへ収録した。探索評価値を正誤には使わない。

実戦4課題は、既存の `max-natural / max-white-h7 / max-white-h6` を使わず、今回別に行ったRapfi対Rapfiの棋譜から採用した。

|sourceId|固定した最初の二手|採用手数|双方の探索時間|
|---|---|---:|---:|
|assessment-selfplay-f7|H8 / F7|20|150ms/手|
|assessment-selfplay-f6|H8 / F6|22|150ms/手|
|assessment-selfplay-k8|H8 / K8|20|150ms/手|
|assessment-selfplay-j5|H8 / J5|20|150ms/手|

各問題に開始盤までの `sourceMoves` と終局までの `sourceRecord` を保持する。全棋譜は黒勝ちで終わる25手の自己対局だが、150msの生成条件であり、アプリ最強8000msへの勝利記録・人間の実戦成績ではない。採用局面からの局所的な勝ちは自己対局の一手順に依存せず、独立した有限証明で再検証した。

K8対局の22手目の盤は全合法初手で勝ちが残り、判断の確認にならないため不採用とした。20手終了時点へ戻し、白の四を受ける必要があり、元からある黒の二方向の攻めが残る盤を採用した。

## 採点・証明の範囲

- 自由五目15×15、五連以上で勝ち、禁手なし。黒番の石数、開始時終局なし、意図しない即勝ちなしを確認する。意図的な四の競争・受け四だけは `intentionalImmediate` へ明記。
- 初手は全合法手を調べる。即五連、局所目標達成、強制四追い、全白応手からの四追いの準備、証明済み白勝ち、未判定を分ける。
- `order` は明示された初手条件 `judge.firstObjective: forcing-four` を持つ。静かな手から別の勝ちがあっても、この確認の「四を続ける」条件には未達なので `goal-miss`。負けとはしない。全accepted経路で、終局前に黒の四が少なくとも2回現れることを検査する。
- `win` の未登録・非強制初手についても全白応手の証明を試み、証明できた別解をすべて `judge.setups` へ登録する。初手だけを暗記した表に限定しない。登録setupの後の白応手は代表表示だが、その採用根拠は全合法白応手。
- 以後のVCF証明では、毎回相手の即勝ちを検査する。黒の四に対する唯一の受け、二つ以上の勝ち口、白が他へ打つと黒が即勝ちになる場合を区別する。単一の白棋譜を「全応手証明」と呼ばない。
- 通常の継続は最大9半手・1,600ノード。探索不発・上限到達は `unknown / correct:null`。証明済みの相手勝ちだけが `proven-loss`。比較・防御条件への未達は `goal-miss` であり、対局の負けを意味しない。
- 正誤の因果説明・反証フレームは `learning.js` の盤面からの説明と、比較問題に同梱した文で提供する。反証は各手合法で最後の白五連までを検査する。仮想反証を本当の着手履歴へ混ぜない。

## 再現検証

```sh
node --test tests/assessment-bank.test.mjs
node scripts/generate-assessments.mjs
```

後者は固定された採用盤から全初手の証明候補を再計算し、解答集合との一致と全白応手の証明を確認する。ランダムに別問題へ差し替える生成コマンドではない。`scripts/generate-assessments.mjs` の窓列挙・VCFは採点APIから独立しており、`game.js` の証明器とも照合する。

検証対象は、レッスン隔離、D4/移動の重複、全合法初手、全登録setupの全白応手、必要な四の応手、全表示分岐の五連までの進行、未判定を誤答にしないこと、反証手順と説明の整合、開始盤と保存復元、準備の四0条件、実戦の完全合法履歴、実データの2familyと白→黒の履歴を使った初回確認台帳への接続。別日保持が成立したとの架空記録は作らない。

現版の検証対象: 盤入力の全7,238合法初手と、31個の登録setupに対する全6,436合法白応手を確認した。`order` の全accepted表示経路は、終局前の黒の四を最低2回含む。これらは数学的・実装上の整合性の計数であり、学校での学習効果の計数ではない。

## 優先判断の条件補充（2026-11-12）

以前のpriority4盤はすべて黒に即五連があり、形の違う2familyを通しても「自分に勝ちがないときに受ける」判断を確認できなかった。問題数を増やさず、options-a/bを新ID defend-a/bの防御条件へ置き換えた。旧IDへの露出を新しい受け問題への露出と誤認しないため、IDも変えている。優先判断は `own-win-first` と `prevent-immediate-loss` の2条件で確認し、同じ条件の2盤だけでは初回確認を成立させない。

新2盤は開始時の黒即勝ち0・白即勝ち1。正しい受けの後は白の即勝ちとforkがともに0となるため、既存prevent-forkの有限採点でその一点だけを受理する。成功文はsuccessTitle/successTextで「白の五連を止めた」「勝負は続く」とし、二重攻撃を防いだという別の達成へ置き換えない。他の全216合法黒手には、元の完成点へ白が置く即五連の反証がある。

通常レッスンの候補は `PRIORITY-DEFENSE-LESSON.json`。`problem` と3個の `lessonFrames`、誤答の2フレーム例を収録した。確認盤とはD4/平行移動でも一致しない。レッスンは「黒に即勝ちがない→白の完成点を探す→受けて続ける」を示す。JSON候補を用意したこと自体は本番レッスンへの統合完了を意味しない。

旧options-a/bは自分の即勝ちを選ぶ問題だったため、旧priorityの2familyを防御条件の証拠へ移植しない。旧familyをown-win-firstへまとめる処理と版の更新はcurriculum/learning-path側で行い、他単元の教材はこの差し替えで変更しない。
