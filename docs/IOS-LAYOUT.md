# 盤面優先のiPhoneレイアウト

2026-11-11。ユーザーの最新指定は、iPhone 15程度の約19.5:9を基準に、画面の45%以上を盤面にすること。タイトルは縮小し、内容更新でUI位置を動かさない。

## 変更

従来は画面高から固定UI・説明欄・セーフエリアを引いて盤の横幅を決定していた。例えば高さ793px、上下59/34pxの条件では盤の外枠が241pxまで縮小する。これを廃止し、盤の幅は常にゲーム領域の100%とした。

- 基準キャンバス: 393×852。端末幅を基準に同比率で拡縮。
- 盤外枠: 393×393。内側の盤本体: 389×389。
- 盤本体の画面面積比: 389² / (393×852) = **45.1926%**。
- 盤枠の装飾を薄くし、余分な左右余白を除去。行座標は盤端の石に重ならない位置に配置。
- ヘッダーロゴ84×28、紋章28×28。ヘッダー44px。
- 下部ナビ56px + ホームインジケータ用safe-bottom。ゲーム枠内へabsolute配置。
- 説明欄は残りの高さで固定し、その内容だけスクロールする。
- 学習全面再構築では対局の教材ショートカットを撤去。最新配置は[再構築の検証](rebuild/VALIDATION.md)に記録。
- 3タブ・仮置き確定・応手再生へ再構築。操作行と情報欄の固定寸法は維持。
- CSS/アプリの読込URLに版を付け、古いレイアウトの混在を避ける。

## iOS 27の表示領域

ユーザーの端末はiOS 27.0.1。WebKitには、ホーム画面版で画面とWebViewの高さが一致しない報告がある。

- https://bugs.webkit.org/show_bug.cgi?id=301994
- https://bugs.webkit.org/show_bug.cgi?id=313800
- https://bugs.webkit.org/show_bug.cgi?id=254868

そこでstandalone時はwindow.innerHeightをキャンバスの高さの上限にする。盤の幅にはこの値を使わず、下部ナビだけを利用可能な範囲に収める。これはWebKitが描画を許可しないネイティブの帯をCSSで消すという処理ではない。

## 確認範囲

ブラウザー検証は393×852に、CSSカスタムプロパティで上下59/34pxのセーフエリアを再現した。実機iOSそのものを自動操作した検証ではない。

通常条件: 盤本体389px、盤外枠393px、下ナビ下端852px。盤本体45.1926%。

利用可能な高さを793pxに制限した条件: 盤本体は389pxのまま、下ナビ下端793px。画面外への操作列の押し出しを防ぐ。OSが確保する残りの領域の挙動は、実機での再確認が必要。

対局・教材・練習で同じ盤幅を確認。盤端A15への確定着手とCPU応手を確認。既存自動テスト37件成功。
